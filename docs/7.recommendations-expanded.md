# Recommendations and Gaps

This document captures concrete, actionable improvements that are missing or
under-specified today. It is intentionally short and prioritized for practical
execution.

## 1. Error taxonomy and logging conventions

- Define a shared error model (domain error codes, HTTP mapping, user-safe
  messages, and internal context).
- Standardize structured logging fields (request id, user id, group id, route,
  handler, duration, db query count, cache hit/miss).
- Enforce consistent logging for errors, retries, and external calls, so logs are
  queryable across services.

## 2. Security hardening checklist

- Add a baseline security checklist for every new feature: authn/authz, input
  validation, rate limiting, CSRF/session handling, secure cookies, and audit
  trail coverage.
- Add content security policy (CSP) guidance for the web app and a checklist for
  sensitive endpoints.
- Define a minimal threat model template and include it in PRs that touch auth
  or data access.

## 3. E2E coverage map and CI gate

- Maintain a lightweight coverage map for critical flows (auth, permissions,
  transactions, sync, multi-currency, auditing).
- Tie E2E coverage to CI gates for critical flows to avoid regressions.
- Provide a fast smoke suite and a full suite, with clear entry points and
  expected runtime ranges.

## 4. Observability beyond logs

- Expand observability to include metrics and traces alongside logs.
- Define core metrics (latency, error rate, queue depth, cache hit rate, db query
  time, websocket connection health).
- Add tracing guidelines and propagate request ids across services.
